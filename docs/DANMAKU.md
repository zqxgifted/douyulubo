# 弹幕转换（XML → ASS）说明

[← 返回 README](../README.md) ｜ [GUI](GUI.md) ｜ [避坑](PITFALLS.md)

本项目内置一套**纯 Python** 的 XML → ASS 转换器（`src/danmaku_ass.py`），
不需要 DanmakuFactory、不需要任何外部程序，因此「解压即用」包里自带全部功能。

## 三种弹幕模式

GUI 的「弹幕处理」下拉框和 `config.json` 的 `danmaku_mode` 控制：

| 模式 | 值 | 行为 |
|---|---|---|
| 下载弹幕并转换 ASS（默认） | `ass` | 拉 XML → 转 ASS，两种文件都保留 |
| 只下载 XML 原始弹幕 | `xml` | 只拉 XML，不转换 |
| 不下载弹幕 | `none` | 跳过整个弹幕环节 |

## 排版算法（防重叠）

这是最容易出问题的地方，所以单独说明。

### 参数

| 项 | 默认值 | 说明 |
|---|---|---|
| 分辨率 | 1920×1080 | 跟随视频常见规格 |
| 字号 | 46 | ASS 的 `\fs` |
| 行高 | 字号 × 1.05 | 轨道间距 |
| 滚动时长 | 8 秒 | 从右边界外走到左边界外 |
| 固定弹幕时长 | 4 秒 | 顶部/底部停留时间 |
| 可用高度 | 屏幕顶部 45% | 滚动弹幕只占这个区域 |

### 滚动弹幕

屏幕宽 `W`，弹幕宽 `w`，速度 `v = (W + w) / 8`（即 8 秒走完 `W + w` 的距离）。

**关键：每条轨道记录该轨道上所有仍在屏幕内的弹幕**，新弹幕要逐一与它们做几何
碰撞检测 —— 而不是只和"上一条"比较。只比上一条是常见错误，会导致与更早的弹幕
重叠。

碰撞判定在时间轴上采样，只比较**屏幕可见区域 `[0, W]`** 内的像素区间
（已经飘出屏幕的部分观众看不到，不算重叠，否则会误判并浪费轨道）。

### 轨道分配

在所有不冲突的轨道中，选**最久未使用**的那条，让弹幕纵向均匀分布，
而不是永远堆在最上面一行。

### 超容量时的降级

如果所有轨道都满（例如每秒几十条的极端刷屏），无法再排纵向轨道，此时：

1. 先尝试把弹幕顺延到最早空出的时刻（最多尝试 2 秒）；
2. 仍不行，就**退化为顶部固定弹幕** —— 它不横向移动，只占一个时间段，
   因此绝不会与滚动弹幕在同一行重叠。

这样极端场景下也保证**零视觉重叠**，代价是部分弹幕变成顶部停留显示。

### 实测数据

| 场景 | 弹幕数 | 轨道 | 视觉重叠 | 耗时 |
|---|---|---|---|---|
| 正常 2 条/秒 | 1200 | 9 | **0** | 0.5s |
| 密集 5 条/秒 | 600 | 9 | **0** | 0.6s |
| 超载 20 条/秒 | 200 | 9 + 固定降级 | **0** | 6.8s |
| 极端 50 条/秒 | 400 | 9 + 固定降级 | **0** | 12.6s |

验证方法：解析生成的 ASS，还原每条弹幕在任意时刻的像素区间，逐帧比对可见部分是否相交。

## ASS 输出细节

- 滚动弹幕：`{\an7\move(1920,y,-w,y)}` —— **必须用 `\an7`（左上对齐）**，
  否则 ASS 默认 `\an2` 会让坐标指向文字中心，整体偏移半个宽度（这是常见 bug）
- 顶部弹幕：`{\an8\pos(960,y)}`，底部：`{\an2\pos(960,y)}`
- 颜色：B站 XML 的十进制 RGB → ASS 的 `&HBBGGRR&`
- 转义：反斜杠和花括号是 ASS 控制字符，替换为全角；换行转 `\N`

## 用外部 DanmakuFactory（可选）

如果你更信任外部实现：

```bash
# 1. 在 config.json 里填 danmaku_factory 路径
# 2. 显式指定后端
node douyu.mjs ass --backend danmaku-factory
```
